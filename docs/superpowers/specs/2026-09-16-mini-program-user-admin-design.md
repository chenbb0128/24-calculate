# 小程序用户管理后台 MVP 设计

## 目标

为现有小游戏项目增加一个独立、可直接运行的用户管理后台前端 MVP。后台使用演示数据模拟真实用户数据，完成用户检索、筛选、查看详情、启用/禁用和批量操作；本阶段不改动现有小游戏前端和 Go API。

## 范围与非目标

### 本阶段包含

- 独立目录 `frontend/admin/`。
- 用户数据概览：用户总数、今日新增、活跃用户、已禁用用户。
- 用户列表：关键词搜索、状态筛选、平台筛选、分页和全选。
- 用户详情抽屉：基础资料、注册来源、活跃概况和最近登录信息。
- 单个启用/禁用、批量禁用，并提供确认反馈。
- 使用 `localStorage` 持久化演示数据中的状态变更。
- 空结果、无选择、加载/操作反馈、窄屏布局。
- 无依赖的浏览器运行方式，并提供 Node smoke test。

### 本阶段不包含

- 管理员账号、登录、权限和审计日志。
- 真实 Go API、MySQL 查询或写入。
- 删除用户、导出数据、复杂报表和实时推送。
- 修改现有小游戏端或生产部署配置。

## 方案选择

采用原生 HTML/CSS/JavaScript 的独立静态应用，而不是在现有小游戏前端中混入管理页面，也不在 MVP 阶段引入 React/Vue 构建链。这样可以无依赖启动、快速验证交互，并为后续替换数据仓库保留清晰边界。

## 页面与交互

页面由左侧导航、顶部标题区、数据概览卡片、筛选工具栏、用户表格和详情抽屉组成。

- 导航默认高亮“用户管理”，其他入口以占位方式展示，体现后续扩展结构。
- 搜索按昵称、用户名和用户 ID 匹配，筛选条件变化后回到第 1 页。
- 表格展示头像、昵称、用户 ID、平台、注册时间、最近活跃和状态。
- 点击一行或“查看详情”打开右侧抽屉；抽屉内操作会即时同步列表。
- 选择多条记录后显示批量操作栏；未选中时隐藏该栏。
- 禁用操作使用确认弹窗；操作完成后通过 toast 告知结果，并刷新统计卡片。
- 过滤无结果时保留筛选条件并展示清晰的空状态。

## 数据与状态模型

演示用户对象字段与现有 `users` 表及平台身份保持语义一致：

```js
{
  id: "U10086",
  username: "wx_10086",
  nickname: "晴天小猫",
  avatar: "…",
  platform: "微信",
  status: "active" | "disabled",
  createdAt: "2026-09-01T10:20:00+08:00",
  lastActiveAt: "2026-09-16T09:18:00+08:00",
  sessions: 128,
  totalMatches: 42
}
```

应用状态拆分为：原始用户集合、当前搜索词、平台/状态筛选、当前页、每页数量、选中 ID 集合、详情用户 ID、确认弹窗状态和 toast 状态。列表通过纯函数从原始集合派生，避免搜索、分页和状态操作互相污染。

状态持久化使用一个命名空间明确的 key，例如 `sanhuo.admin.users.v1`。首次加载读取内置演示数据，之后只恢复用户状态字段，避免旧数据结构破坏页面。

## 文件边界

- `frontend/admin/index.html`：页面骨架、语义化区域和交互挂载点。
- `frontend/admin/styles.css`：颜色令牌、布局、表格、抽屉、弹窗、响应式样式。
- `frontend/admin/app.js`：演示数据、状态派生、渲染和交互事件。
- `frontend/admin/tools/smoke_test.js`：无需第三方依赖的行为测试，直接加载可测试逻辑并断言结果。

暂不拆分更多模块，以保持 MVP 易运行；当接入真实 API 时，将把数据访问抽成独立 adapter，不改变页面交互接口。

## 错误处理与可用性

- localStorage 不可用或数据损坏时回退到内置演示数据，不阻断页面使用。
- 批量操作没有选择时显示轻量提示，不触发状态变更。
- 找不到详情用户时关闭抽屉并提示数据已更新。
- 所有可操作控件提供可见 hover/focus 状态、按钮文案和 aria-label。
- 颜色不作为唯一状态线索，状态同时使用文字和色点/标签表达。
- 窄屏下表格允许横向滚动，详情抽屉改为底部/全宽面板，保证核心操作可达。

## 测试与验收

Smoke test 覆盖：

1. 搜索能匹配昵称、用户名和 ID，并在无结果时返回空集合。
2. 平台和状态筛选可组合，筛选后页码重置。
3. 分页不会超出边界，最后一页数量正确。
4. 单个启用/禁用与批量禁用只改变目标用户。
5. 状态序列化后重新加载可以恢复，损坏的存储会安全回退。
6. 页面脚本可在浏览器中加载且不抛出初始化错误。

验收方式：运行 `node frontend/admin/tools/smoke_test.js`，再用静态服务器打开 `frontend/admin/index.html` 做一次桌面宽度和窄屏宽度交互检查。

## 后续接入真实后端的边界

后续接入生产链路时，只替换用户数据 adapter 和操作方法：列表改为调用管理员用户列表接口，状态操作改为带管理员权限的 API，前端保留当前筛选、分页、详情和反馈层。管理员认证、权限和审计属于单独阶段，不在本 MVP 中假设或模拟。

## 后续后端制作与验收清单

开始制作真实后端时，必须单独确认以下事项，不能用前端演示数据代替：

- 用户提交的昵称和头像都经过微信内容安全审核；审核中的结果返回 `MODERATION_PENDING`，审核拒绝分别返回 `NICKNAME_REJECTED` 或 `AVATAR_REJECTED`。
- 历史违规昵称已经完成替换，并清理数据库、缓存和相关读取链路中的旧资料缓存。
- 用户资料接口返回约定业务码 `NICKNAME_REJECTED`、`AVATAR_REJECTED`、`MODERATION_PENDING`、`NICKNAME_EDIT_DISABLED`，前端按业务码展示可理解的提示。
- 审核失败时不覆盖原昵称或头像；只有审核通过后才写入新资料，审核中的资料也不能破坏现有可用资料。
- 微信 AppSecret 只存在后端环境变量或后端密钥配置中，不进入小游戏包体、后台静态资源、日志、接口响应或提交记录。
- 完成数据库迁移，并在后端目录执行 `go test ./...`，以通过结果作为后端阶段完成条件。

当前 A 版只保留这份验收约束，不实现真实审核、迁移或 API 调用；后端阶段开始时应先按清单补充接口、迁移和测试设计。
