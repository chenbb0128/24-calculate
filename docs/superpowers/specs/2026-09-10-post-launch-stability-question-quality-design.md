# 上线后稳定性与题目质量防护设计

## 目标

为原生微信小游戏前端增加一层可复用的运行稳定性和题目质量保护，优先解决线上题目无解、服务端合同异常、重复提交结算难以定位，以及玩家无法提供有效故障信息的问题。

本阶段只修改 `frontend/wechat_game`，不修改 backend、Godot 原型或其他小游戏项目。

## 范围与非目标

### 本阶段包含

1. 服务端题目进入游戏前的统一本地可解性校验。
2. 闯关、每日、无尽、好友对战使用同一套题目质量判断结果。
3. 题目质量失败时阻止开始，保留“重试”入口，不使用未验证的本地随机题替代正式服务端题目。
4. 记录题目 ID、题目数字指纹、质量校验结果和当前模式，便于诊断。
5. 结算请求的前端幂等锁，防止重复点击造成重复提交。
6. 线上异常本地记录扩展，以及一个不依赖新页面的“问题反馈/复制诊断信息”入口。
7. 开发审计脚本覆盖上述规则。

### 本阶段不包含

- 不新增后端接口，也不修改服务端结算规则。
- 不在正式环境使用本地奖励、本地结算或本地题目替代服务端 Run。
- 不改头像授权、对战房间协议、商城价格、广告策略和 UI 主题。
- 不把完整答题过程或用户隐私上传到第三方。

## 设计

### 1. 题目质量边界

新增 `question_quality.js`，只负责无副作用的验证。它接收题目合同和可选规则，输出：

```js
{
  ok: true,
  key: "1,3,5,9",
  puzzleId: "...",
  reason: "",
  solutionSteps: [...]
}
```

验证顺序固定为：四个整数、数字范围、目标为 24、每个数字只能使用一次、整数中间结果、允许运算符、已有解法合同可执行、生成器完整求解至少存在一个解。只返回必要的诊断字段，不把完整解法展示给玩家。

服务端题目必须先通过此边界才进入 `this.puzzles`。如果失败，模式控制器清空当前题面、标记启动失败并返回房间/模式入口；不得继续开始一局“可能无解”的游戏。

### 2. 题目指纹与诊断

`question_quality` 提供稳定的数字指纹和题目摘要。`telemetry.js` 负责：

- 记录启动失败、题目质量失败、提交失败、运行时错误、重复提交拦截；
- 通过现有 `storage.appendErrorLog` 保存到当前账号命名空间；
- 限制条数、字段长度和单条大小；
- 默认不联网、不上传题目解法、不上传头像昵称；
- 需要时生成可复制的短诊断文本。

`feedback_service.js` 只负责从诊断上下文生成玩家可读的反馈和复制动作，复制失败也只能提示，不得抛出未捕获异常。

### 3. 结算幂等

`GameApp` 为 campaign/daily/endless/friend 各维护当前结算请求状态。进入提交方法前按 `mode + run_id/match_id + attempt_count` 生成请求键；相同键正在提交或已完成时直接忽略。网络失败允许用户重试，但不会清除仍有效的 Run checkpoint，也不会发放本地奖励。

### 4. 与现有架构的连接

- `question_service.js` 继续负责生成、静态题库和各模式题目获取；只调用质量模块，不迁移其职责。
- `mode_controller.js` 在服务端题目合同进入 `this.puzzles` 前调用统一校验。
- `game_app.js` 负责界面状态、错误提示、结算幂等和调用诊断；不把校验细节写入绘制代码。
- `diagnostics.js` 继续负责报告摘要，新增 telemetry 的最近事件数和最近质量失败摘要。

## 错误处理

| 情况 | 行为 |
| --- | --- |
| 服务端题目无解/合同不完整 | 不开始游戏，记录原因，显示“题目校验失败，请重试” |
| 正式后端启动失败 | 保持现有正式环境不回退本地题目/奖励规则 |
| 本地记录写入失败 | 继续显示错误提示，不能阻断主循环 |
| 结算重复点击 | 忽略重复操作，保留一次请求 |
| 结算网络失败 | 显示“等待结算/重新提交”，不发放本地奖励 |
| 复制诊断失败 | 显示可手动复制的短文本，不抛异常 |
| 校验模块异常 | 由模式启动捕获，回到入口并记录错误 |

## 验收标准

1. 每个正式服务端题目在进入游戏前都经过统一 `validatePuzzle`。
2. 一个不能算出 24 的题目会被拦截，不会出现空白卡片或死机。
3. 相同题目合同的指纹稳定，不因数组重新排序产生误报。
4. 同一结算键只允许一次提交；失败后可用同一键重试。
5. 线上异常可在本地错误日志中看到模式、屏幕、题目指纹和阶段。
6. 375×667、393×852、414×896、750×1334 的现有布局审计继续通过。
7. 现有好友房、Run 恢复、授权、排位 UI 测试不回归。
