# 微信小游戏上架准备清单

当前项目仍以 Godot 4.7.1 桌面原型为主，微信端暂未迁移。本文件把迁移边界固定下来，后续可以把玩法代码映射到微信小游戏页面，而不需要重写题目规则。

Godot 项目已加入 `export_presets.cfg` 的 Web 预览预设。Web 预览用于提前检查竖屏布局、触摸按钮、音频和资源加载；它不是微信小游戏最终运行包，也不能代替微信开发者工具真机测试。

根据当前电脑的磁盘要求，项目已准备 D 盘便携版 Godot：`tools/Godot4.7.1Portable/`。它使用自包含的 `editor_data/`，后续导出模板、编辑器缓存和项目工具均放在 D 盘；C 盘已有 Godot 安装保持不动。

## 已准备好的部分

- `core/puzzle_generator.gd`：题目生成、穷举验题、解法记录与特殊规则验证。
- `core/match_data.gd`：单机、每日、无尽、好友对战共用的题目/答题记录结构。
- `core/friend_match_service.gd`：同题竞速房间、固定种子和结果计算。
- `services/platform_adapter.gd`：广告、分享、排行榜、存档的统一平台边界。
- `services/save_service.gd`：Godot 原型使用 `user://twenty_four_progress.json`，迁移时改为微信本地缓存或云存档。

## 微信端 API 映射

| 原型能力 | 微信小游戏实现 | 数据归属 |
| --- | --- | --- |
| 进度/金币/皮肤 | `wx.getStorageSync`、`wx.setStorageSync` | 本地缓存 + 云端备份 |
| 看广告获得提示/撤销 | `wx.createRewardedVideoAd` | 客户端触发，服务端校验奖励条件 |
| 好友邀请 | `wx.shareAppMessage` | 房间号和题目种子放 query |
| 好友战绩/全局榜 | 云开发云函数或自有 HTTPS 服务 | 服务端 |
| 好友对战结果 | 服务端提交答题记录并校验 | 服务端 |
| 登录身份 | 微信登录态/云开发身份 | 服务端 |

## 必须遵守的迁移规则

1. 题目可以由客户端生成用于显示，但通关结果、排行榜和好友对战胜负不能只相信客户端。
2. 好友对战双方必须使用同一个 `room_seed` 或服务端下发的题目列表。
3. `wx.createRewardedVideoAd` 只有在 `onClose` 返回完整观看时才发放奖励；加载失败不能扣除玩家次数。
4. 本地存档只能作为缓存，正式上架后金币、关卡进度、皮肤购买和排行榜需要云端校验/备份。
5. 每日挑战日期统一使用中国时区的服务端日期，不能直接依赖玩家设备时间。
6. 所有分享文案和房间 query 只放房间号、种子等非敏感信息，不放用户隐私。

## 上架前验证顺序

1. 先导出 Godot Web 原型，验证触摸、竖屏、音频和包体表现。
2. 再将 `core/` 和 `services/` 中的纯逻辑迁移到微信端 JS/TS，并保持字段名一致。
3. 接入微信本地存储，模拟清缓存、重复领取、跨天和断网场景。
4. 接入云函数/服务端，验证好友对战同题、防篡改和排行榜提交。
5. 最后接广告、分享、隐私协议、投诉入口和小游戏审核配置。

## 当前明确风险

Godot 不是微信小游戏的官方一键发布链路。Godot Web 导出可以帮助验证玩法，但不能直接视为微信小游戏最终包。正式上架前仍需单独完成 WebGL/小游戏运行时适配、触摸输入、音频策略、资源包体和微信审核测试。
